Guard the paid X path behind an explicit flag, add a Buffer channel lister, deploy

Four TWITTER_* secrets were still on the deployed worker. With routing based on
"a network is on when its secrets are present", deploying before the Buffer
secrets existed would have sent the next cron straight back down the paid path
at 0.20 USD a post, which is the exact bill this work removes. The paid path now
also requires X_PAID_ENABLED to be the string "true", so leftover credentials
cannot bill anything on their own. Turning X off again is deleting one flag
rather than four secrets.

bot/buffer-channels.mjs prints the channel ids straight from Buffer's GraphQL
API. Reading them through the worker meant deploying before you could configure
the thing the deploy depends on, and it confused "is my key valid" with "is my
worker up". No dependencies, Node 18+.

Deployed to statedoku-twitter-bot.sachabitoun17.workers.dev. Verified it answers
403 without a key and with a wrong one, and that with no Buffer secrets set it
resolves to no networks at all, so it currently posts nowhere and bills nothing.

Recorded in the README: production still serves the v1 bank, so the worker falls
back to a generic tweet until the site is pushed.
